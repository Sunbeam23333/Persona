# 共用聊天列表引擎

选择独立的 `:core:chatlist`：窗口、阅读位置和滚动规则不依赖消息协议，也不属于设计 token。Agent、助手、飞书可以各自提供数据和行样式，复用同一套行为。

`ChatListWindow<T>` 接收消息标识、顺序和未读计数条件。拖动时冻结实际数据，更早的页和冻结边界以内的补洞仍能加入，边界之后的新行暂缓显示。回到最新后解除冻结。计数排除自己发送的消息和工具事件，并可根据实测可见边界、已读游标排除已看到的消息。

`rememberChatListState`、`ChatListEffects` 和 `ChatList` 负责倒置列表、首次定位、手势冻结、远端预取、回最新及阅读位置。页面传入按最新到最早排列的行标识，包含待发消息，不包含分页控件。`ready` 应在数据和行投影都准备好后开启。完成未看传入最后一条用户消息所在行的 `ChatListEntry`，用 `reportLastLine` 提供文本布局测出的末行高度。飞书可传入事项入口行。进入定位按标识跳转后读取布局修正，不使用固定等待时间。

`ChatAnchorStore` 是持久化接入接口，键由 hub 与配对代次组成的作用域、带来源前缀的会话标识组成。保存行标识、行内偏移、跟随状态及展开集合。实现方须提供不阻塞界面的缓存读取和有序持久写入，生命周期写入不能依赖页面协程继续存活。平时采用设计规定的防抖，退到后台和离页立即调用写入接口；未注入时只提供 Compose 状态恢复。

下一轮 App 接线：向 `ChatScreen` 传入 `readingKey` 和 `anchorStore`，Agent 与助手均使用该入口；存储由 hub 作用域持有，切换配对时清理。飞书车道引入本模块，提供窗口排序、入站未读条件、游标分页、入口行和可见已读上报。分页仍由数据源负责，Agent 保留现有按轮请求及工作折叠，无新增 HTTP 接口。

数据源只能提供同一条连续且已核对的窗口。断档后的整窗替换应重建窗口及列表状态，不能把不连续的页传给冻结窗口合并。已读上报须同时检查前台、定位完成、无遮挡、非程序滚动和数据已核对；ChatScreen 已保留这些门禁并限制游标只向前。

验证范围为窗口合并、计数、预取门禁及末行偏移计算的单元测试，以及聊天模块编译。未做真机、深浅色截图或长会话滚动验收，性能未实测。回最新按钮采用 Material 3 语义色，标签单行。
