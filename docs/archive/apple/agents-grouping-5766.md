# iPhone Agents 分组与首批长列表上限（#5766）

## 本批范围

- 快速筛选下方的独立 List 单元提供分组菜单，共用原 `dev.grouping`；按状态、项目、机器和最近使用等原选项与默认值保留。静态搜索框只响应明确点击或无障碍激活，不把 UIKit 菜单焦点探测当作开始搜索。
- 长组首次显示前 20 项，超过 25 项时提供「显示全部」；搜索与快速筛选不截断，tab 内的 Agent 不拆散。
- iPhone 之外的客户端维持原布局和列表上限行为。
- 这是首批缓解。用户随后明确实际规模为 **8000 个 Agent**，后台索引、缓存、客户端分页与差量更新另做下一批；本报告不能作为 8000-Agent 验收。

## 400-Agent 受控测量

baseline 与测量分支均基于 `34aa498cf52332d9af252b2bb68993bbcc4a498c`；分支只应用本任务补丁。Xcode 27.1、优化 Debug（`-O`、wholemodule），iPhone 17 Pro / iOS 27.0 模拟器。Xcode 26.0 未验证。

每种分组交替运行 baseline / 分支，3 轮；每轮约 8 秒静止推送（12 轮推送）和 6 秒自动滑动（2000 pt/s，下 3 秒、上 3 秒）。使用现有 `FrameStats`（`-showPagePerf YES -perfCounts YES`）。所有模拟器操作按单次持有 `/tmp/playbox-sim.lock`，所有编译使用 `xcode-slot`。

30 份 API fixture 快照均有 400 个唯一非助手 Agent、408 个总 session。两侧状态分布相同：工作中 53、需要你 14、空闲 192、完成未看 140、离线 1。60 份测量 JSON 完整；所有静止段收到推送，对比脚本退出码 0。

## 结论边界

- 按机器和最近使用的滑动差异接近零，不宣称显著提速。最近使用的静止推送段掉帧有所减少；按仓库仍有推送期间卡顿。
- 三轮模拟器采样不是统计显著性证明，也不保证真机持续渲染 60 FPS。
- 平铺模式限制了首次可滚动内容，相同速度和时长并不经过相同数量的行；不能把列表缩短直接解释为每帧渲染效率提高。
- 旧「140-Agent」批次实际只有 133 个非助手 Agent，并混有不同基底改动；它只作为探索性数据保全，不混入上述读数。
- 读数对应行数上限原型。最终 UI 将分组菜单置于独立单元，并将开始搜索限制为明确点击或无障碍激活；布局及无键盘回归另行验证。没有追加 400-Agent 测量，也不以原型读数保证最终菜单布局的逐帧表现。
