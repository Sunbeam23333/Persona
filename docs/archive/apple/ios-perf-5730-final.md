## 口径与可比较性

- FPS 是 **CADisplayLink 回调 cadence**，不是 GPU 实际呈现帧率。hitch 是自定义迟到时间，不是 Instruments 官方 hitch。run-loop busy 墙钟时间不是 CPU 时间。
- 机器/收件箱采用 App 持有的固定 UIKit 列表 glide：2000 pt/s、每方向 3 秒、1 轮显式 warm-up + 5 轮正式样本；实际位移及原始样本归属已验证。复用原基线，不重跑。
- Agents 数据为负责人公布的 400-Agent、各分组 3 轮原型读数；列表上限改变经过的内容，最终菜单布局另做功能验证，没有重测 FPS。不是 8000-Agent 或最终布局逐帧验收。
- 主对话/设置旧测量含 XCUITest 手势和可访问性快照开销，标成 **旧诊断**，不能与 App 内 glide 合并比较。最差值从原附件离线提取，不使用旧摘要的中位最长帧代替最差帧。
- 除 sparkline 的同基底隔离对比外，其余本会话批次间主线及主机负载并未完全隔离。机器详情原始基线与后续页面高度不同；后两批高度/位移相同，也不因此成为统计因果证明。

## 未达标原因与建议（仅建议，不继续开工）

1. **机器详情 390 ms：根因尚未精确确认。** 已确认并移走单机指标同步解码、点 ID/gap/peak 准备、无关推送造成的时间域变化及逐点 Mark 构造。但最终仍有约 356 ms 的 run-loop busy 区间；旧无 XCUITest 采样有 Swift Charts 链路，不能将重叠采样节点计为 CPU 百分比，也不能据此把最终这条长帧全部归到 Charts。建议在长帧触发时捕获真实主线程栈和刷新 signpost，区分图表 scale/layout、其他监控/额度卡片和主机调度；再决定保留交互/外观的几何路径缓存或其他绘制方式。本轮不继续实现。
2. **机器网格：** 仍有 4/5 轮小 hitch，路径复用不能消除刷新/布局成本；建议分离可见卡片刷新及图形投影缓存，维持原视觉和数据及时性。
3. **Agents：** 400-Agent 原型按状态的一轮 437.68 ms 长帧在原始数据中存在；不能只引用 PR 的 hitch 中位数。建议由其负责人区分推送/分组/布局成本；8000-Agent 分页和差量工作是独立任务，不能由这份 400-Agent 报告代替验收。
4. **收件箱：** 同口径最差值基本不变，单遍缓存是避免重复主线程工作及复制，不是帧率显著提升证据。建议在真实连续推送/搜索条件下定位新增卡顿，不重复执行静止缓存测试来证明收益。
5. **主对话、会话详情、设置及未测页面/跳转：** 旧自动化开销与 App 成本没有分离，操作微基准也不足以推出页面 FPS。建议后续先做真实设备/标准时间窗的按需测量，优先持续流式、输入和用户常用跳转；本轮不扩展测量或优化方向。
